# 3.1.6 开发方案：统一元数据文档与正文隔离

2026-10-16 · ACCEPTED / 开发及隔离验证完成。用户批准开发、隔离测试及提交推送 dev；PR 由用户手动创建，不授权合并、生产数据操作、部署或发布。

## 审阅入口与建议

详细字段分类、统一文件样例、迁移和保存规则见 [元数据统一文件与正文隔离设计](./metadata-storage-design.md)。本文只维护交付范围与任务，避免重复两套契约。

Profile 是表单管理定义，没有用户手写的完整 sing-box 配置；configs JSON 是同步序列化文件。资源库保存用户节点/模板/规则集 JSON。两者均将管理信息与定义/正文分离，最终产物只读取构建所需定义和纯资源。

推荐每个工作区只新增一个 `sing-sub/metadata.json`，内部按实体路径归集 note/order/已知时间、display、editor 信息；不再新增 resource-meta/profile-meta/逐实体文件。在线 R2 用同一 revision 的 metadata 区，不额外维护 R2 元数据对象。

## 批准范围

1. 定义 ProfileDefinition、纯资源 content 和统一 EntityMetadata；Profile/资源的 note/order/时间迁入唯一 metadata 区，去掉原持久化副本。Profile 旧毫秒时间转 UTC ISO；不新增或回填未知资源创建时间。
2. 规则集 _sing_sub 的来源与手写编辑定义迁入同一记录的 editor.ruleset；展示顺序放 display；保留编辑能力与来源时间，最终规则集正文仅含 version/rules。
3. 管理子对象注释按明确方向/唯一 tag 迁移到 editor.annotations。歧义/未知字段生成报告并阻断，不能丢弃；合法业务 headers 等同名键原样保留。
4. 一次业务保存原子更新正文+元数据；typed 局部 command 保护其他记录，expectedRevision 防止并发覆盖。排序不更新实体时间、不抓取来源、不 dispatch SRS。
5. 新快照写 v4，读 v3/v4；同步 manifest/表示 v3、读旧 v2；metadata 文档 schema v1。旧 base 按原投影验证，不清空基线掩盖格式差异。
6. 旧混合格式集中转换，明确导入本地排序；不长期双写。构建入口只接收纯定义/资源，各输出的隔离回归成为上线门槛。

## 文件职责

| 位置 | 唯一职责 |
|---|---|
| GitHub configs/nodes/templates/rulesets | 纯 Profile 定义与用户业务正文 |
| GitHub metadata.json | 唯一新增管理元数据文件，按实体路径分区 |
| GitHub manifest.json | 现有生成清单、文件大小/hash，不复制管理字段 |
| R2 revision | 定义/content 与 metadata 分区的一致性快照，以及原工作区运行字段 |
| R2 head/private/jobs/artifacts | 原事务指针、连接/凭据、任务和产物协议 |
| localStorage/内存 | 设备偏好/临时交互与可推导状态，不进入统一文件 |

## 验收门槛

- 所有已知管理字段有唯一保存位置；新正文和 ProfileDefinition 不含管理 note/order/时间/_sing_sub，资源合法业务键及数组/对象字段顺序不丢失。
- 管理测试值不能出现在预览、订阅、公开规则集和 SRS 编译源；headers 等合法同名字段保持，规则合并与筛选输出不变。
- 两设备读取顺序一致，清空 localStorage 不丢服务端数据；新增/复制/改名/删除同时更新记录，局部保存不覆盖其他实体，旧设备不自动抢写。
- 服务端维护修改时间；排序/无变化保存/SRS 不刷新实体时间；来源观测时间和配置时间各自正确。
- 规则集 editor 可从 metadata 完整恢复；IDE 改正文后不会被旧 editor 静默覆盖；缺失/损坏新格式 metadata 不能按空数据清掉编辑信息。
- 单文件白名单、路径/数量/大小、重复 JSON 键/身份、时间、类型、注释 tag 歧义、非法操作和并发 409 均有测试，失败不部分落库。
- 仅备注/排序变化可同步；旧 v2 base/仓库、新格式缺失文件、孤立记录、过期 manifest、多轮往返不伪造 hash/时间或产生循环差异。
- v3/v4 读写、restore/recoverHead/retention、历史原 hash/sync base 校验和代码+数据+同步树联合回滚通过；原历史 revision 不改写。
- GitHub 恢复正文与 metadata 原子应用，不导入部署身份/安全版本/凭据/运行状态；派生构建按现有协议重建。
- 生产桌面/移动/Firefox、五档视口、双语/主题、鼠标/触摸/键盘及保存失败通过；lint、全部类型、unit/integration、构建、三段 gzip、许可证、Worker dry-run 和文档检查通过。
